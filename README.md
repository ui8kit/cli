# ui8kit CLI

Shadcn-style registry CLI: `init` / `add` / `list` / `diff` / `info` / `scan` / `build`. It fetches registry items from a CDN and **writes source files into your app** (not into `node_modules`), so Tailwind sees the classes.

npm package **`ui8kit@3.x`** · registry digest **`@ui8kit/registry@3`** (per-runtime `r/<runtime>/`) · runtimes **react, vue, svelte, solid, webcomponent** · config contract `2.0.0`

**Docs:** [docs/README.md](./docs/README.md) · **Upgrading from 2.x:** [docs/migration-v3.md](./docs/migration-v3.md) · **Agents/maintainers:** [AGENTS.md](./AGENTS.md)

## Idea

```text
@ui8kit/registry@3/r/<runtime>/   →  npx ui8kit@3 init  →  {dir}/utils/…  +  .cursor/rules/ui8kit-primitives.mdc
                                  →  npx ui8kit@3 add   →  {dir}/ui/<brick>/…
```

Primitives are generated by ui8kit codegen and published per runtime; this CLI installs them.

## Requirements

- Node.js `>=20` (or Bun)
- A project with `package.json` (created by `init` if missing). Vite/React are **not** required.

## Quick start

```bash
npx ui8kit@3 init --yes --framework react --dir src
npx ui8kit@3 add button text stack
```

- `init` writes `ui8kit.config.json`, installs `registry:utils` into `{dir}/utils` (plus npm peers `clsx`, `tailwind-merge`) and the `registry:rules` item into `.cursor/rules/ui8kit-primitives.mdc` (`{kit}` → your primitives folder, `{globs}` → files under `dir`). Only folders of files actually written are created.
- `add` installs bricks into `{dir}/ui/<brick>/` and resolves `registryDependencies` (`slot`, `utils`, …).

Other runtimes: `--framework vue|svelte|solid|webcomponent` (Web Components install `*.wc.ts` + shared files).

## Layout under `{dir}`

| Path | Role | Registry type |
|------|------|---------------|
| `ui/<brick>/` | primitives (codegen) | `registry:ui` |
| `utils/` | `cn`, `variants`, … — **required by primitives** (`../../utils`) | `registry:utils` |
| `.cursor/rules/` (app root) | agent rules for the primitives | `registry:rules` (installed by `init` only) |
| `components/`, `blocks/`, `layouts/`, `lib/`, `variants/`, `widgets/` | other item types (brand registries) | `registry:component` / `block` / … |

Remap safely at the same depth (e.g. `"paths": { "ui": "kit" }`); keep `utils` at `{dir}/utils`. Precedence: `--path key=dir` > `config.paths` > file `target` — see [Configuration](./docs/configuration.md).

## Registry version

- **Default = CLI major**: ui8kit 3.x fetches `@ui8kit/registry@3` → `…/r/<runtime>/` (newest 3.x.y; not pinned).
- **Pin**: `--registry-version 3.0.0` or `"registryVersion": "3.0.0"` (ranges like `3.1` and dist-tags like `canary` work too).
- **Server runtimes** (templ, latte, twig, jinja2) are first-class in 3.2 (`r/<runtime>/` of `@ui8kit/registry@3`); see [Server runtimes](#server-runtimes-templ-latte-twig-jinja2).

CDN order: `--registry-url` / `registryUrl` → `cdnBaseUrls` → built-in unpkg / jsDelivr. `--strict-cdn` + explicit URL → only that URL. URL `registryDependencies` resolve bare names against the item's own registry base. Details: [docs/cdn-and-cache.md](./docs/cdn-and-cache.md).

## Server runtimes (templ, latte, twig, jinja2)

```bash
npx ui8kit@3 init --yes --framework templ --dir internal     # or latte / twig / jinja2 (e.g. --dir templates)
npx ui8kit@3 add button
```

- `init` writes only `ui8kit.config.json` (`typescript: false`), `ui8kit.lock.json`, `.cursor/rules/` and `{dir}/utils` (templ), `{dir}/runtime` (twig/latte) or `{dir}/ui8kit_jinja` (jinja2). No `package.json`, no tsconfig; `add` does not require a `package.json` either.
- **Toolchain deps are never installed automatically** and never go to npm. After `init` / `add` the CLI prints the exact commands once (deduped) from the item `meta`: `go get github.com/a-h/templ@v…`, `composer require "twig/twig:^3.0"`, `pip install "Jinja2>=3.1,<4"` (double quotes: works in bash, PowerShell and cmd).
- **templ**: generated code imports `github.com/ui8kit/codegen/generated/templ/utils`. With a `go.mod` in the app root the CLI rewrites it (in `*.templ` and `*.go`) to `<module>/<utils dir>`, e.g. `example.com/app/internal/utils`. Without `go.mod` the import is left as is and a warning prints the fix: `go mod init <module>` + `ui8kit add <items> --force`, or replace the import by hand. Then `templ generate && go build ./...`.
- **twig / latte**: the CLI prints a PSR-4 snippet (`"UI8Kit\\Twig\\": "<dir>/runtime/"` / `UI8Kit\\Latte\\`) for your `composer.json`; it never edits `composer.json`. Run `composer dump-autoload`. Twig: `$twig->addExtension(new \UI8Kit\Twig\TwigExtension())`.
- **jinja2**: `ui8kit_jinja/` sits next to `ui/`; `from ui8kit_jinja import environment` → `environment().get_template("ui/button/button.html.j2").render(p={...}, children=...)`.
- `ui8kit check` works the same. Note: `templ generate` rewrites `*_templ.go` (e.g. source `FileName` paths), so `check` reports those files as `modified` afterwards; re-adopt with `check --adopt` or treat `*_templ.go` as build output.

## Config (`ui8kit.config.json`)

```json
{
  "$schema": "https://cdn.jsdelivr.net/npm/@ui8kit/registry@3/schema/schema.json",
  "contractVersion": "2.0.0",
  "framework": "react",
  "runtime": "react",
  "typescript": true,
  "dir": "src",
  "globalCss": "src/index.css",
  "aliases": { "@": "./src" },
  "registry": "@ui8kit",
  "importStyle": "alias"
}
```

`--import-style package` (`@ui8kit/core` imports) is **deprecated**: it still works but prints a warning.

## For app developers: lock, `check`, versions

### `ui8kit.lock.json`

`init` and `add` record every installed file in `ui8kit.lock.json`: the registry it came from (`source`, the URL actually used), the **exact** version (`3.0.0`, never a range) and a sha256 per file. **Commit it** — it is how you (and CI) know the kit on disk is exactly what the registry shipped. Do not edit it by hand.

```bash
npx ui8kit@3 check            # offline, no network; exit 1 on errors
npx ui8kit@3 check --json     # machine-readable report
```

Add `npx ui8kit@3 check` to CI (see [CI scenario](./docs/scenarios/ci-and-upgrades.md)). Existing app installed before 3.1 (no lock): run `npx ui8kit@3 check --adopt` once — it fetches the registry, hashes what each item would install and adopts **only files that match**; others are listed as `not-adopted` (decide: re-install with `add <name> --force`, or keep as your own file). Commit the lock.

| `check` error | Meaning | Fix |
|---------------|---------|-----|
| `missing` | a locked file was deleted | `npx ui8kit@3 add <name> --force` |
| `modified` | file content differs from what was installed — a local edit, **or** `aliases` / `importStyle` / `paths` changed after install (import rewrites change content) | revert the edit (`add <name> --force`) and move styling to `className` / tokens; after a deliberate config change re-install the items with `--force` |
| `mixed-versions` | primitives from one registry are on different versions (e.g. `button` 3.0.0, `text` 3.1.0) | `npx ui8kit@3 add <outdated…> --force` (or `add --all --force`) so all share one version |
| `rules-version` | `.cursor/rules/ui8kit-primitives.mdc` is from another version than the primitives | re-run `npx ui8kit@3 init` with your flags (refreshes utils + rules), or bring the primitives to the rules version |

Line endings: hashes are computed with CRLF normalized to LF, so `git config core.autocrlf true` on Windows is **not** reported as `modified`.

### Registry version

The default registry is the **CLI major** (`ui8kit@3` → `@ui8kit/registry@3`, newest 3.x.y). To make installs reproducible, pin an exact digest: `"registryVersion": "3.0.0"` in `ui8kit.config.json` (or `--registry-version 3.0.0`). Upgrade deliberately: change the pin, `add --all --force`, `init` (rules), `check`, commit.

### Brand registries

A brand registry (e.g. `https://registry.buildy.tw/react`) ships blocks / composites that **depend on** the primitives by URL (`registryDependencies: ["https://cdn.jsdelivr.net/npm/@ui8kit/registry@3.0.0/r/react/components/ui/button.json"]`) and records the digest it was built against in `registry.json` top-level `meta` (copied to `index.json`):

```json
{ "meta": { "primitives": { "registry": "@ui8kit/registry", "version": "3.0.0" } } }
```

Brand items get their own lock entries (key per registry identity), separate from `@ui8kit/registry`.

**Primitives are not forked.** Do not edit files under your kit folder (`{dir}/ui`, `{dir}/utils`) — `check` reports it, and `add --force` would overwrite it. Brand styling goes through `className` on the primitives and design tokens (CSS variables / Tailwind theme); new UI goes into your own components or a brand registry.

## Commands

| Command | Purpose |
|---------|---------|
| `init` | config + utils + agent rules |
| `add <names…>` / `add --all` | install items (`--runtime`, `--dry-run`, `--force`, `--path key=dir`) |
| `check [--json] [--adopt]` | verify files against `ui8kit.lock.json` |
| `list` / `diff` | browse registry / compare local files (read registry settings from config) |
| `info [--cdn]` | environment and resolved CDN order |
| `scan` / `build` | author a registry: `src/registry.json` → `r/` |
| `cache clear` / `registry clean` / `reset` | maintenance |

Full reference: [docs/commands.md](./docs/commands.md).
